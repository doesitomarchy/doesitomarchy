Methodology

DoesItOmarchy tracks whether Omarchy works on every Intel Mac Apple sold from 2006 to 2020. Each Mac is identified by its model identifier (for example MacBookPro8,2, shown in System Information), and every official hardware configuration is listed as a complete computer. This methodology sets the rules for turning test results into a status, so a verdict means the same on every Mac, whoever tested it and with whichever tool, and anyone can check how it was reached.

TLDR;

  • Only tests countEvery capability starts Untested. Only a test someone runs and reports changes a status; research notes never do.
  • Known limitationsGPUs that reach only OpenGL ES 2.0 can't run Hyprland 0.50 or later. They carry a warning note, which never changes a status.
  • ConfigurationsEach Mac is split by the parts Linux cares about (GPU, Wi-Fi, audio, ports…), and each configuration gets its own verdict.
  • VerdictsA failed Boot criterion makes a configuration Failed; any other failure makes it Partial. The Omarchy mark means every criterion that applies has passed.
  • Newest report winsFor each criterion, the report from the newest Omarchy version counts. Reports from an older major version are marked stale.
  • CoverageCounts configurations that passed everything and those with any report. Macs from before 2009 and the Xserve are left out of the figures, but can still be tested.
  • Port groupsPorts on the same controller behave alike, so one passing port covers its whole group.
  • Test criteriaEach configuration shows only the criteria that apply to its hardware, generalised from Boyd's Vintage Mac Compatibility Test Criteria.
  • SourcesHardware facts come from Apple, EveryMac, OpenCore and linuxhw probes of real machines. Every model page lists its own.

Only tests count

Every capability starts as Untested. A status only changes when someone runs Omarchy on that configuration and reports the result. Research notes on model pages come from spec sheets and Linux hardware probes. They are labelled unverified and never change a status.

Known limitations

Some hardware rules a feature out before anyone tests it. Hyprland, Omarchy's desktop, has needed OpenGL ES 3.0 since version 0.50, so it can't run on a GPU whose Linux driver reaches only OpenGL ES 2.0. Configurations with such a GPU carry a {{template "icon" "alert"}} known-limitation note. Like research notes, it never changes a status. On those GPUs the GPU-acceleration criteria fail on stock Omarchy: a workaround that runs Hyprland in software (Mesa's llvmpipe) or a GLES 2.0 fork of Hyprland doesn't make them pass, and testers record it in the notes. Search gles:2.0 lists them.

Configurations

A release is split into configurations when the parts Omarchy Linux cares about differ: the GPU, Wi-Fi, Bluetooth, Ethernet, audio codec, storage controller or security chip, or the ports and features that decide which tests apply. CPU speed, RAM and disk size are attributes of a configuration, not separate ones. Rebadges of the same chip share a configuration. Each configuration is named by what sets it apart from its siblings, such as its GPU, screen size or release.

Ports and port groups

Some criteria are tested on each port, such as USB data or external display. Testers don't need to try every port: ports on the same controller and driver behave alike on Linux, so they form a port group. Usually that's all the ports of one type. A few Macs split them, such as the MacBook Pro (15-inch, 2016) [MacBookPro13,3], whose left and right Thunderbolt 3 pairs sit on two controllers. USB-C charging is the exception: charging is handled below the operating system, so all of a Mac's USB-C ports are one group for it.
